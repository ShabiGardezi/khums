## 2. Rule Builder and engine capabilities added

- A deduction may be limited to named counted entries (`against`): costs reduce only their own
  income, never below zero, so a business loss never offsets salary (Sistani 1790; Khamenei's
  several-jobs note).
- Per-entry confirmations may name deduction entries (spending, debts, purchases).
- New deduction type: price paid for things still held at year end; costs of earning may include
  business debts; up to 20 confirmations per rule.
- Scholar requests, rejection and AI preparation status (P4-1).
- All compile to existing engine operations: no new expression kind, no pack schema change,
  earlier revisions keep their hashes. The rule form edits every new field.
- Nisab: asked as a factual confirmation against the stated metal weight (the texts state it in
  gold or silver weight, so a fixed money threshold would need a metal price anyway).

## 3. Rules stored in the actual database — NOT YET

The migration was **not performed**. Every connection to the Atlas cluster is refused during the
TLS handshake (`tlsv1 alert internal error`), from this session and from your own terminal,
while other internet access works. This is the usual result when the computer's current IP
address is not on the cluster's Network Access list, or when the cluster is paused. Changing
Atlas network access is an infrastructure change I do not make. Nothing was written to Atlas.

### Runbook (once Atlas accepts the connection)

All commands run from `apps/api` (after `pnpm --filter @khums/api build`) unless noted.

1. Atlas console → Network Access: allow this computer's current IP (or resume the cluster).
2. Read-only check: `node dist/main.js --inventory-database > inventory-before.json`.
3. Additive migration (creates `scholarRuleRequests` with its indexes; never drops or rewrites
   data): `node dist/main.js --migrate-database`.
4. From the repository root, fetch the offices' text into the git-ignored caches:
   `node scripts/fetch-office-passages.mjs docs/research/bundles/sistani/bundle.json` and the same
   for `khamenei`.
5. Start the API locally against Atlas (`pnpm --filter @khums/api dev`) and the web app pointing at
   it, then import, signing in with **your own** staff account when prompted (the password is not
   echoed, stored or printed): `KHUMS_BASE_URL=http://localhost:3000 node
scripts/import-research-bundle.mjs docs/research/bundles/sistani/bundle.json`, then `khamenei`.
   The import stops before writing anything if the Marja already has rules it did not create, or
   if an earlier import's state file is missing; it never revises a scholar's revision.
6. Re-run step 2 and compare.

Expected result: Sistani 4 sources, 378 passages, 66 findings, 5 rulings (453 research records)
and 5 rules; Khamenei 2 sources, 181 passages, 69 findings, 5 rulings (257 records) and 5 rules;
all DRAFT, all rules "Approved for scholar testing by AI".

**Deployment order matters:** the data uses values only the new code understands (new AI
involvement types, deduction fields). The deployed API must run this code before or together with
the migrated data.

## 5. Unsupported or incomplete (annual) — and why

Entry types no rule counts stop as "uncovered — needs individual review": cash, bank and wallet
balances (counting them would double-count income), sale proceeds, investment returns, receivables,
digital assets, joint ownership, khums paid during the year, unpaid khums, "other".

| Topic                                                                            | Marja    | Why not calculated                                                                               |
| -------------------------------------------------------------------------------- | -------- | ------------------------------------------------------------------------------------------------ |
| Investment returns, bank profit                                                  | Sistani  | Neither 1769 nor 1770 addresses them; bank profit depends on agency and the bank (Jami' 676–678) |
| Bank profit and deposits                                                         | Khamenei | Liable only above inflation: needs an inflation input                                            |
| Gain on selling property                                                         | Both     | Needs purchase price, sale price and (Khamenei) inflation, and no-offset across kinds            |
| Rise in value of business stock held from earlier years                          | Both     | Needs last year's taxed value (carry-over) and, for Khamenei, inflation                          |
| Inflation-only rises                                                             | Sistani  | Obligatory precaution (Jami' 647): a scholar decision by design                                  |
| Receivables, wages owed, credit-sale mark-up                                     | Both     | Present value or collection-year choice (Jami' 715; Khamenei)                                    |
| Savings exceptions (marriage steps, emergency savings, five-day window)          | Khamenei | Savings are balances; the exceptions need dates and the person's circumstances                   |
| Several occupations with separate years; people without an occupation            | Both     | Separate yearly cycles need date logic                                                           |
| Debts for lasting needs carried to later years                                   | Sistani  | Needs carry-over of the remaining deductible balance (704; Q&A 7)                                |
| Khums paid during the year, or from later income (quarter rule)                  | Both     | Gross-up rule (Jami' 721; Khamenei Q246–247) not encoded                                         |
