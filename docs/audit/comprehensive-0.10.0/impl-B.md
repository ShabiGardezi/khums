## Limitations

- Exact price↔asset pairing needs an engine feature (entry count, or `forFactId` link on
  ASSET_PURCHASE facts); a false `ft-price-entered` / `ft-price-item-owned` answer can still misplace
  a price.
- `ft-value-current` relies on the person's answer; a `DatePolicy` requiring valuedOn = assessmentDate
  would be the engine-side check.
- Empty first-time sheet still gives 0 (UI should require an entry).
